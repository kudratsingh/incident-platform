# Architecture decision records

Every decision that constrains future work gets a record here. An ADR is written once and then left alone: when a decision changes, a later ADR amends or supersedes it and both stay on the shelf, so the reasoning that was true at the time is still readable.

Status is stated in each file's own header; the table below mirrors it. All 26 are accepted — the interesting column is the last one, which says where a decision has since been narrowed.

Three gaps with one shape: state the reset does not sweep, with nothing in its own output to say so. A breaker is reset by rewriting its record *closed* rather than deleting it, because an absence is not a reading ([0030](0030-breaker-state-is-published-and-a-reading-is-never-invented.md)) — and because the in-process registry (ADR 0006) would write the same failure straight back, the reset raises a signal carrying *when* it happened, which every breaker honours before it publishes again and before it refuses another call. The evaluator's guards and world audit must wear the agent's token, because that token is what they are asserting about, so their rows were indistinguishable from the agent's own work in the `/demo` ledger. The label needs a second credential (`X-Lab-Principal`, holding `chaos:invoke` or the read-only smoke account by name, same tenant, `CHAOS_ENABLED` only) or the subject under test would be writing its own audit label; an unauthorised field is refused rather than ignored, because an ignore leaves the row mislabelled *and* the caller believing otherwise. | [0039](0039-the-platform-pages-on-its-own-metric.md) | The platform pages on its own metric, and an episode raises once | Accepted | Owner decisions O-35 and O-36. Makes the metrics pass interval a setting (`METRICS_LOOP_INTERVAL_SECONDS`, default 60, **5 in the demo stack**) and derives from it the two numbers that were literals beside it — the lag value key's TTL, now three passes rather than a fixed 90 s, and the 15-minute lag window, now pruned by TIME rather than by a count of passes, so the span is the promise and the density follows the clock (15 samples at 60 s, 180 at 5 s). Then adds the two rules the platform evaluates on its own tick: `consumer_stalled` on the latest MEASURED lag sample, `dlq_depth_warning` on a tenant's dead-letter total, each raising once per episode through a `dedup_key` carrying an episode ordinal — counted from rows, because a Redis marker would be one more piece of state the reset has to sweep and forgetting it would silence the NEXT take ([0036](0036-the-reset-closes-a-breaker-and-a-registry-it-cannot-restart-honours-it.md)'s class of defect). A recorded constant is never a breach, and an absent reading is neither a breach nor a recovery: unknown is not zero. `alert.raised` / `alert.resolved` audit rows carry the page for the console to draw, written in the alert's own transaction and withheld from NOBODY — [0012](0012-the-lab-is-invisible-to-the-agent.md) hides the lab, and an alert is the one row the agent is supposed to have. The one contract delta is `get_consumer_lag`'s description, which had "every ~60s" and "90s TTL" in it and would have been lying on the one stack anybody watches; it now names no interval and points at `age_seconds`, and must not interpolate the setting or the pinned snapshot would differ per deployment. No migration, no new table, column, key, scope or refusal code; builds on 0006, 0012, 0015, 0025, 0026, 0027, 0028, 0036 and 0037 |
